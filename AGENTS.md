# OrchFlow agent instructions

Read [IMPLEMENTATION_PLAN.md](IMPLEMENTATION_PLAN.md) and [README.md](README.md) before changing this repository. Update the plan as milestones are verified; distinguish implemented functionality from proposed work.

- Windows desktop application, PowerShell, Rust backend, React + TypeScript frontend, React Flow graph editor.
- Use upstream OpenUSD for USD semantics. Never substitute a mesh-only loader and describe it as full USD support.
- Keep native USD/rendering work outside the UI thread. Report missing runtime dependencies and renderer capabilities honestly.
- Each OrchFlow project owns only its single JSON file. Application-wide settings live separately in applications.json. All external USD, native projects and assets stay at their original locations and are linked in a shared dependency registry. Do not create managed project/node folders, separate node JSON, copies or symlinks. Saving/relinking must not write external files. Explicit app editing/publishing is a separate authorized action with user-selected destinations.
- For application nodes, the native project is the editable source and published USD is the downstream artifact. Reopen existing native projects; upstream changes require explicit reconciliation, never automatic reimport over native edits.
- Adapters declare import/export/automation/schema capabilities. Mesh-only applications must not silently replace a complete upstream scene; geometry overlay layers are an option where stable prim mappings make them safe.
- Axis/unit conversions must be reversible and recorded per round trip. Metadata changes alone are not geometric conversion.
- Each third-party application profile owns target up-axis and unit preferences. Nodes can override them; additional scale defaults to 1. Snapshot the resolved settings and forward/inverse matrices when preparing a native project; publishing must use that snapshot, never newly changed global preferences. Existing native projects require explicit migration if their coordinate convention changes.
- Validate graph data at the backend boundary; reject cycles and dangling edges before execution.
- Keep domain operations independent of Tauri so a future MCP server can reuse them. The local stdio MCP server now reuses these domain operations; keep its project saves and explicit artifact writes separate.
- Run `npm run build`, Rust formatting, and relevant Rust tests/checks for changes. Document checks that cannot run.
- Do not claim a real USD viewport or application round trip works until tested with a real stage and application.
- Leave screen-based/manual verification to the user; do not use screen interaction tools unless requested. Use builds, automated tests, and non-UI measurements for verification and clearly state the remaining manual check.
- AI-related repositories belong under `I:/AI`. ComfyUI is at `I:/AI/ComfyUI-Github/ComfyUI`; models, workflows, and custom_nodes are outside its installation. Target hardware: RTX 3090, 64 GB RAM.

- Asset Override nodes own a modal dependency grid scoped to their connected upstream USD assets. Relink and Find Missing register replacement links and author branch-local in-memory USD overrides; never globally mutate original registry paths. Browse stage reuses existing entries with a warning. Missing originals remain valid links.


- Combining graph inputs must preserve USD reference/instance sharing. Reuse distinct source stages, namespace inputs by stable edge identity, and author node transforms outside instanceable references. Generated preview stages/layers remain anonymous in memory. Multi-root normalization may flatten only a private layer-stack snapshot once per distinct input, preserving composition arcs; never flatten/copy geometry per branch or edit original layers.

- Material interoperability direction: preserve incoming networks/bindings by default; prefer MaterialX with a UsdPreviewSurface fallback while retaining native materials in original application projects. Conversion/baking/replacement must be explicit, capability-gated operations. Verify topology/UV correspondence before geometry-only overrides, and preserve instance sharing where compatible. Material policy and external dependency links live in the single OrchFlow JSON; see the material phase in IMPLEMENTATION_PLAN.md.
- Discover USD references (including unresolved shader assets) into the registry without editing originals; retain authored-path provenance so explicit relinks survive rescans. Referenced-node usage is read-only/derived. Find Missing searches only the chosen directory tree, preserves ambiguous choices, and never guesses among multiple candidates. Pin previews by stable node ID and invalidate only for the pinned upstream subgraph.

- Existing Blender native projects can be reopened using the configured executable dependency and direct process arguments. Treat a returned process ID as a launch request only; it does not prove load/save/publication. Blender first import, conversion snapshots and selective publishing are implemented; other launch adapters and native reconciliation UI remain pending. Never silently reimport when opening a native project.

- Coordinate preflight records prospective `coordinateDraft` settings only. Do not treat it as a completed native-project snapshot or apply it when reopening existing files. Preserve recorded drafts when profile preferences change; require recheck/reconciliation. Actual first import records its own import/export options, baseline and native identity separately.

- Explicit Create handoff USD writes one user-selected .usd/.usda snapshot using upstream OpenUSD flattening. Preserve scene instancing, recorded coordinates and identities; bake current composed scene opinions and active variants while keeping texture assets external. Do not create supporting .layers folders. Graph evaluation remains non-destructive/in-memory. Explicitly confirmed replacement of an OrchFlow-generated handoff is allowed; atomically replace its single file. Protect source files. This is distinct from project save and portable packaging. Record handoff IDs/conversion separately from native/published links. Application Handoff/Published preview selection is display-only and must not change downstream published-output semantics.

- Do not force instanceable wrappers around inputs containing UsdSkel Root/Skeleton schemas: the pinned USD 25.08 imaging adapter fails on those nested skeleton prototypes. Keep reference arcs and static-mesh instancing. No legacy handoff compatibility repair is requested; regenerate old skeletal handoffs explicitly.

- Blender first-import adapter is implemented but full execution/visual verification is assigned to the user. Do not run Blender import tests without a renewed request. Preserve recorded nativeImport provenance; never overwrite/reimport a linked native project. Toolbar insertion shifts reachable downstream nodes once and preserves unrelated layout and graph metadata.

- Application-wide defaults/capabilities live only in the user application configuration JSON, edited in Applications. Nodes own profile IDs, edit scopes and overrides. Never restore project-level profiles or add compatibility migration for this redesign. Snapshot copies on handoff/native records are historical provenance, not configuration.
- Fail closed for unknown/unverified capabilities and enforce scope in the backend, not only checkbox state. Profile edits require increasing revisions; do not mutate historical snapshots or silently reconcile native edits. Capability declarations authorize only implemented, validated operations. Selective publication uses baseline comparison and must fail closed on unsafe correspondence.

- Selective publishing requires adapter v2 immutable baseline, matching round-trip identity, recorded input graph/dependency revisions and an explicit reviewed token. Preserve input-only data and native-import provenance. Author only allowed deltas into new user-selected root/edit layers; never promote a raw export directly as an application output. Changed scope requires explicit authorization against the unchanged baseline; changed coordinates/adapter/input require reconciliation. No legacy baseline reconstruction or migration.

- Explicit **Reconcile upstream** reuses the last published sparse adjustment layer over newly composed connected input, using the publication's frozen coordinate convention. No conflict review or automatic Blender reimport/export is requested. Stronger node opinions win at matching USD paths; ordinary USD attributes/arrays are replacements, not element-wise additive deltas. Preserve native/baseline/handoff provenance and prior output files. Register new reconciled input/root/edit layers only after success.
- Prune strictly identical property values/connections/metadata from newly generated adjustment layers. Retain necessary USD declarations, changed complete arrays and meaningful removals. Do not flatten upstream geometry or omit an edit simply because an upstream change happens to match it during later reconciliation.

- Undo/redo is session-only project history. Group node drags and focused inspector edits, exclude selection/measurements/camera and derived discovery, clear history on project open, and keep native text-field undo. Undo changes JSON links/settings only; never delete/undo external generated files or third-party application edits.
- Bundled ZBrush, Marvelous Designer and Substance Painter profiles are templates, not implemented launch/native-import adapters. Retain documented restrictions, vendor references, provisional coordinate notes and disabled unverified scopes. Add missing templates without overwriting custom profiles or historical snapshots.
- The `orchflow` stdio MCP server is configured in Codex and built at `I:/AI/OrchFlow-build/debug/orchflow-mcp.exe`. Prefer its domain tools for test projects and headless stage inspection/rendering. It does not control the active desktop session; explicitly load/reload saved test projects there. Do not run Blender tests without the user's request. MCP protocol stdout must contain only JSON-RPC; renderer logs go to stderr.
- MaterialX nodes explicitly author Standard Surface networks with a UsdPreviewSurface fallback, optional external color/roughness textures and stronger branch-local bindings. Preserve incoming networks and instance sharing. Do not claim automatic shader conversion, baking, arbitrary graph authoring or OpenPBR authoring. Whole-input binds apply at the root; reject instance-proxy subprim targets rather than silently de-instancing. `.mtlx` writes require a new user-selected destination and must not copy textures.

- Auto material preview is selective: trace connected material networks to missing shader assets, replace only affected networks in private preview layers, and retain valid materials/subset bindings/instance sharing. Never author renderer fallbacks into source layers or published graph output. Scene/Solid remain explicit alternatives; missing unconnected assets may be diagnosed without disabling healthy shading.

- Keep application sidebar compact: Allowed edits is a closed rollup; new profile selections default to all supported capabilities only. Never silently expand existing prepared scopes. Application executable browsing/editing belongs in Applications globally. Node coordinate/scale controls are hidden under Coordinates and scale. Application input comes from connected Source nodes; do not reintroduce an Additional input picker. Create handoff USD and Create native project remain separate explicit actions.

- Explicit first-import creation may replace an unlinked destination .blend and its baseline after user confirmation. Validate new outputs before installation, retain uniquely named backups, and roll back on installation failure. This does not authorize automatic reimport of a linked native project or rewriting historical import records.

- Manual baseline workflow supersedes automatic baseline capture for newly created Blender projects. Create native project writes the .blend only and records nativePreparation; the user exports and selects an unedited baseline and matching edited USD. Preserve old nativeImport records. Manual baseline records must validate stable handoff IDs, source revisions and immutable fingerprints; unedited state/export settings are explicit user attestations.
- Selected-only manual exports match stable object IDs, never guessed names or root paths. Preserve all objects outside baseline selection. Missing exported prims never delete upstream objects; use the explicit Delete graph node. Additions need explicit root approval and implemented capability/scope checks. Selective handoff settings live on the Application node; keep unselected upstream objects in live outputs, preserve selected subtrees/ancestor transforms and required material/rig dependencies in the handoff, and reject proxy-child selection without de-instancing.

- Explicitly confirmed publication replacement may overwrite the generated root/edit pair. Preserve backups, validate staged composition and restore originals on installation failure. Source/baseline/edited files stay protected. A new publication revision must invalidate same-path graph previews.

- Live application adjustments supersede generated publication/reconciliation files. Apply reviewed edits stores frozen sparse USD opinions and provenance in the one project JSON, reconstructing anonymous layers over the live upstream graph. Ordinary upstream changes recompose automatically; never reimport Blender or recalculate native edits automatically. Guard topology/identity and baseline/edited revisions. Explicit Export final USD is the only application-output disk write. Preserve old external publication files and links until the user explicitly replaces the node's output with a live adjustment.

- MaterialX rule editor is non-blocking and movable; rows own simple/regex selectors and shader settings. Validate selectors/settings in the backend, preserve prim namespaces and instances, report skipped proxies, and apply last-matching-rule precedence. Texture files remain shared external dependencies; no backdrop may block canvas editing.

- Manual Application baseline/edited files may be USD, polygon OBJ or Alembic (.abc), with matching formats. Source/handoff/final output remain USD. Convert OBJ in anonymous layers only; Alembic uses upstream usdAbc with explicit missing-reader errors. Interpret OBJ/Alembic axis/units from the frozen handoff convention disclosed at baseline selection. Keep explicit correspondence, topology/vertex checks, capability/scope checks and immutable-baseline guards. Preserve incoming USD materials; no implicit OBJ MTL conversion or full-scene Alembic interchange claim.

- Generated namespace v2 keeps Source assets under /Scene/<asset-root>, single-input adjustments/transforms at the same paths, and branch containers only at real multi-input merges. Handoff conversion is on /Handoff itself; application return conversion is on /Scene itself. Do not reintroduce Units/Asset, Inputs/Input, Handoff/Input or PreservedInput wrappers. Preserve source hierarchies and instance boundaries. No automatic migration of previous handoffs/adjustments: reject old namespace provenance with clear fresh-round-trip instructions and retain saved user data.

- The viewport supports Storm and standalone NVIDIA Omniverse RTX.
